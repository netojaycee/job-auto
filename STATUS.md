Triggered by the user wanting to cold-email a researched list of recently-funded African/Nigerian startups for engineering roles. Running the actual campaign surfaced four real, previously-latent bugs — not hypothetical, each one blocked a real send until fixed.

- [x] **Fixed: every worker CLI entrypoint's `dotenv.config()` silently loaded nothing** — 2026-10-02. `scheduler:start`, `agent:run`, `ingest:run`, `score:run`, `prepare:run`, `leads:run`, `outreach:run` all called `dotenv.config()` with no path, which only finds `.env` if cwd happens to be the repo root. `pnpm --filter @job-auto/worker <script>` always sets cwd to `apps/worker`, which has no `.env` of its own — so `scheduler:start` failed outright with `DATABASE_URL is not set` the first time it was actually run as a long-lived process this session (earlier "verified live" runs in Phases 2/3 apparently worked under different invocation conditions that happened to set cwd differently). - [x] **Fixed: no way to reconnect Gmail once connected** — 2026-10-02. `/profile`'s `GmailConnection` component only rendered the "Connect Gmail" button when `connectedAt` was empty; once connected it permanently showed only "Connected {date}" with no way to re-trigger OAuth. Real impact: Google caps refresh-token lifetime to 7 days for OAuth apps still in "Testing" publishing status (not yet verified/published) — the dev user's connection from 2026-09-24 expired exactly on schedule mid-campaign, and there was no UI path to fix it short of DB surgery. Verified live: reconnected successfully, new 7-day token confirmed in `application_channels`.
- [x] **Fixed: tailored CVs could contain literal "[Email omitted] / Phone omitted / LinkedIn omitted" text** — 2026-10-02, caught in a CV that had already been sent (to Stabyl) before this was noticed. Verified live: subsequent real sends (BFREE, CreditChek, Platos Health, HoneyCoin) rendered a real email in the header, no placeholder text. **Resend the Stabyl CV if a corrected version matters** — the one already sent predates this fix.

One stale process had been running since well before the send-gate flags were ever enabled or the contact-email fix was deployed; a second, correctly-configured one was started later. Both consumed from the same `manual-outreach` queue, so which env/code a given job ran under was effectively random — this, not a logic bug, was the actual cause of several confusing inconsistent results during the campaign (sends that silently skipped despite flags being "on," per-job behavior that didn't match the latest code). Found via `ps aux | grep scheduler/daemon`; killed the stale PID. **Lesson for next time:** if a long-running worker process's behavior looks inconsistent across consecutive runs with no code/env change, check for a duplicate process before debugging the "logic" — `tsx` doesn't warn about this, and nothing in the project surfaces it automatically.
- [x] **Real cold-outreach campaign run, deliberately supervised** — 2026-10-02. 6 real, independently-verified companies (funding claims and contact channels checked via web research before any pitch was written; 2 originally user-supplied companies — Terra Industries, Flowmono — were dropped for failing verification).
